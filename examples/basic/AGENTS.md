# Project instructions

## Rule: concise

Prefer clear, focused changes with explicit trade-offs.

Keep each change to one concern, so a reviewer can judge it without holding the
rest of the branch in their head. When more than one reasonable approach exists,
say which you picked and what it costs, rather than presenting the choice as
inevitable.

---

## Agent: reviewer

Review changes for correctness, clarity, and maintainability.

Lead with the failure a change could cause, then the reasoning. Name the input
that breaks rather than the principle that was violated, and say plainly when a
change looks correct so the author knows what you actually checked.
