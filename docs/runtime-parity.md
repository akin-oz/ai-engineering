# Runtime parity plan

## Problem

In v0.1, an adapter owns an output directory. That is too narrow for a usable
runtime installation: Claude Code also needs a root-level `CLAUDE.md`, and
Codex needs a root-level `AGENTS.md` in addition to its `.codex/` directory.
Hooks, manifests, metadata, and future runtime assets have the same issue.

Runtime parity means:

> If a target is enabled, its adapter generates every supported artifact needed
> to use that runtime, with no manual runtime-specific setup.

The compiler core must not know which files a runtime needs. The adapter owns
that definition and its complete rendering behavior.

## Required adapter contract

Keep the current `id` and `render(manifest)` exports. Evolve the contract with
an optional declared surface and lifecycle methods:

```js
export const id = "claude";

export const surface = {
  version: 1,
  artifacts: [
    { id: "root-instructions", kind: "file", path: "CLAUDE.md" },
    { id: "runtime-directory", kind: "directory", path: ".claude" },
    { id: "hooks", kind: "directory", path: ".claude/hooks" },
  ],
};

export async function validate(manifest) {}
export async function render(manifest) {
  return { files: 3, artifacts: ["root-instructions", "runtime-directory", "hooks"] };
}
```

For backward compatibility, an adapter without `surface` remains valid and is
treated as owning only `manifest.resolve.output(id)`. The built-in adapters in
the next release must declare a complete surface. A future major release can
make `surface` mandatory.

The surface declaration is metadata for validation and diagnostics, not a
second source of truth for rendering. The adapter remains responsible for
producing the declared artifacts and may create additional internal files under
its owned directories.

The adapter contract should establish these invariants:

- artifact paths are relative to the project root;
- root-level files must be explicitly declared;
- paths cannot escape the project root or overlap `.ai/`;
- two enabled adapters cannot silently own the same path;
- an adapter replaces all of its managed paths atomically;
- output is deterministic for the same manifest and source tree;
- an adapter never reads another adapter's generated output;
- `validate` performs capability/input checks without writing files;
- `render` returns an artifact summary suitable for CLI output and tests.

## Target surfaces for the next release

The exact runtime support should be encoded in the adapters and tested as a
contract. The initial built-in surfaces are:

| Adapter | Required artifacts | Ownership |
| --- | --- | --- |
| Claude | `CLAUDE.md`, `.claude/`, supported `.claude/hooks/`, commands, agents, rules, and any Claude metadata supported by this release | Claude adapter |
| Codex | `AGENTS.md`, `.codex/`, supported Codex hooks, and any Codex metadata supported by this release | Codex adapter |

The source of runtime-neutral content remains `.ai/`: rules, agents, hooks,
commands, templates, and generated workflow content. Each adapter maps that
content to the runtime's complete surface. Runtime-specific defaults, wrappers,
or manifests may live in the adapter package and must be rendered
deterministically.

Do not claim support for an artifact until the adapter can validate and render
it. For example, if a Codex hook format is not yet supported by the current
Codex integration, validation should report that clearly rather than copying a
file that Codex will ignore.

## Rendering model

The current `replaceDirectory(staging, output)` helper is sufficient for a
single directory but cannot safely manage root-level files. Add a shared
artifact transaction used by adapters:

```text
adapter.validate(manifest)
  -> resolve declared artifact plan
  -> stage files and directories
  -> verify paths and collisions
  -> atomically replace managed artifacts
  -> return artifact summary
```

An adapter may use one staging directory under the project root, then rename
each staged root file and managed directory into place. The implementation must
not delete an unrelated user file merely because it is adjacent to a managed
artifact. It should remove stale files only when they are recorded as owned by
the adapter.

To make stale-file cleanup safe, write a small generated ownership record for
each adapter, for example under `.ai/state/targets/<id>.json`, containing:

```json
{
  "adapter": "claude",
  "surfaceVersion": 1,
  "paths": ["CLAUDE.md", ".claude"]
}
```

The ownership record is compiler state, not runtime configuration. It allows a
surface change to remove an artifact that was generated by an earlier sync,
while refusing to delete files that were never owned by AI Engineering OS.
If state cannot be introduced in the next release, adapters must preserve the
current conservative behavior and document that removed root artifacts require
manual cleanup; the preferred implementation is the ownership record.

## Adapter-specific changes

### Claude

1. Keep the existing `.claude/` directory mappings.
2. Add deterministic generation of root `CLAUDE.md` from the shared rules,
   agents, and runtime-neutral workspace context.
3. Define the supported hooks and commands in the surface.
4. Render Claude-specific metadata only when the adapter supports it.
5. Replace the managed root file and `.claude/` contents atomically, preserving
   unrelated project files.

`CLAUDE.md` should be generated from a template owned by the Claude adapter or
the shared template layer, but its content must be derived from the same
normalized manifest as `.claude/`. This prevents the root instructions and
directory rules from drifting.

### Codex

1. Move the current `AGENTS.md` generation from `.codex/AGENTS.md` to the
   required root-level `AGENTS.md`.
2. Keep `.codex/` for Codex-specific configuration, hooks, and supported
   metadata.
3. Add explicit hook mapping and validation rather than treating hooks as an
   arbitrary copied directory.
4. Define the generated root file and `.codex/` paths in the surface.
5. Preserve deterministic ordering and stale-output cleanup.

The source template currently named `codex-agents.md` should be renamed or
reclassified as a root `AGENTS.md` template during migration. A compatibility
fallback may read the old path, but `ai sync` must produce the new complete
surface.

## Compiler-core changes

The core changes should be limited to orchestration and safety:

1. Extend adapter validation to validate an optional `surface` declaration.
2. Build a global ownership table for enabled adapters before rendering.
3. Reject root-path collisions with a diagnostic naming both adapters.
4. Call optional adapter `validate` methods during `ai validate` and before
   `ai sync`.
5. Add shared path validation and artifact transaction helpers.
6. Return artifact summaries from `compile`, while preserving the existing
   `targets: [{ id, files }]` shape.
7. Keep adapter-specific paths, templates, and runtime semantics out of the
   compiler core.

The existing adapter registry remains the extension point. No runtime switch or
Claude/Codex conditional should be added to `compile`.

## Bootstrap behavior

`ai init` should continue to be safe and idempotent. For the next release:

- it must initialize the shared source directories and valid default templates;
- enabled targets in the initial manifest must correspond to installed built-in
  adapters;
- `ai sync` immediately after `ai init` must generate every declared artifact,
  including `CLAUDE.md`, `AGENTS.md`, `.claude/`, and `.codex/`;
- the CLI should print artifact-level summaries so missing root files are
  visible;
- `ai validate` should fail before writes when a required runtime capability is
  unavailable.

The current `init` behavior creates a minimal schema 1 workspace, so the first
implementation can satisfy this without introducing the workflow blueprint:
expand the default source/template set and the built-in adapters first. The
workflow compiler can later feed the same adapter surface.

## Implementation plan for the next release

### 1. Freeze the contract with tests

- Add adapter-surface validation tests for relative paths, root files,
  duplicate paths, and invalid artifact kinds.
- Add a compile test proving two adapters cannot claim the same root file.
- Add a compatibility test proving a legacy adapter with only `id` and `render`
  still compiles.

### 2. Add shared artifact ownership and transactions

- Implement path normalization and ownership validation in the filesystem or
  compiler layer.
- Implement staging for a mixed set of files and directories.
- Record managed paths and remove only previously owned stale artifacts.
- Make failure cleanup leave the previous complete installation untouched.

### 3. Expand Claude

- Add the root `CLAUDE.md` renderer and template.
- Declare and test `.claude/`, hooks, commands, agents, rules, and the root
  file as one surface.
- Verify a second sync is byte-for-byte deterministic and removes stale managed
  content without removing unrelated files.

### 4. Correct and expand Codex

- Generate root `AGENTS.md`.
- Generate `.codex/` content and supported hooks through the same transaction.
- Add fixture tests for every supported Codex artifact and unsupported-hook
  diagnostics.
- Add a migration test that replaces the old `.codex/AGENTS.md` output without
  touching unrelated `.codex` files.

### 5. Complete bootstrap and CLI reporting

- Update init templates and help text to describe a complete generated runtime.
- Add an integration test for `init -> sync` with both default targets enabled.
- Report `Compiled claude: CLAUDE.md, .claude/...`-style artifact summaries.

### 6. Document and release

- Update the adapter API as the compatibility reference.
- Add a release note describing new root-level managed files and stale-output
  ownership behavior.
- Keep schema 1 manifests valid and avoid rewriting user-owned source files.

## Acceptance criteria

The next release is complete when all of the following are true:

- A fresh `ai init && ai sync` produces a usable Claude and Codex installation.
- Claude includes both `CLAUDE.md` and `.claude/`.
- Codex includes both `AGENTS.md` and `.codex/`, including every hook declared
  supported by the adapter.
- `ai validate` detects missing source inputs and unsupported runtime features.
- Repeated syncs are deterministic.
- Removed generated artifacts are cleaned up only when previously owned.
- Root-level collisions are diagnosed before any output is changed.
- Existing schema 1 workspaces and legacy adapters continue to compile.
